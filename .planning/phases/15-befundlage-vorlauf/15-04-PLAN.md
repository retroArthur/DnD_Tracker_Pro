<objective>
Die drei DM-Screen-Referenzwidgets Gelaende, Fertigkeiten und Wissensgebiete rendern wieder
gestylt — indem das CSS an das Markup angeglichen wird, das die Renderer heute tatsaechlich
erzeugen, und nicht umgekehrt.

Purpose: CSS und JS sind bei diesen drei Widgets zwei Generationen auseinandergelaufen. Die
Fertigkeits-Kopfzeilen sind der schaerfste Fall: das CSS definiert eine Klasse, das JS erzeugt
eine andere — zwei verschiedene Zeichenketten, kein Spezifitaetsproblem, gar kein Treffer. Weil
das Markup aller drei Widgets in dedizierten Charakterisierungs-Snapshots eingefroren ist (Phase 13),
ist die Richtung der Reparatur vorgegeben: CSS folgt dem JS (D-09). Und weil das bestehende
64-Test-Netz ausschliesslich Deklarationstext prueft, konnten drei Widgets ungestylt rendern, ohne
dass etwas rot wurde — deshalb kommt die Abnahme diesmal aus berechneten Endwerten am gebauten
Buendel (D-17).

Output: Ein neuer Playwright-Spec, der berechnete Endwerte misst; umgeschriebene Widget-Regeln in
`dmscreen.css`, deren Attributfarben aus den kanonischen Attribut-Tokens kommen (D-13); und eine
neue Ratsche, die die Zahl der regelfreien Widget-Klassen nur noch sinken laesst.
</objective>
